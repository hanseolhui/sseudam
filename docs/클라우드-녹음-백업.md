# 클라우드 폴더에 녹음 원본 보관

설정 → 백업·업데이트 → 내 클라우드 폴더에도 백업에서 폴더를 정한 뒤 **녹음 원본도 이 클라우드 폴더에 자동 백업**을 따로 켠다. 기본값은 꺼짐이다. 켜는 순간 기존 음성 파일도 해당 클라우드로 전송되므로 저장 공간과 전송 대상을 확인한다.

쓰담 실행 중 시작 후 약 90초, 이후 한 시간마다 새 파일과 변경 파일을 확인한다. ‘지금 백업’으로 즉시 실행할 수도 있다. 기존 기록 ZIP과 엑셀의 하루 한 번·최근 30개 보관 정책은 그대로다.

녹음은 `쓰담-녹음-<기기번호>/audio/` 아래에 기존 연도·월 폴더 구조로 보관한다. 같은 파일을 매일 중복 저장하지 않는다. 같은 경로의 내용이 바뀌면 교체 전 파일을 `.history/`에 남긴다. 원본에서 지운 파일과 변경 전 사본은 자동 삭제하지 않으므로 장기 보관 용량은 늘어날 수 있다.

`manifest.json`에는 상대경로·크기·SHA-256 검증 정보가 담긴다. 파일을 다 쓰고 검증한 뒤 최종 이름으로 바꾸며, 전체 작업에 성공했을 때만 목록과 마지막 확인 시각을 갱신한다. 읽기·쓰기·용량 오류는 설정 화면에 표시하고 다음 확인에서 다시 시도한다. 외부 파일을 가리키는 심볼릭 링크는 따라가지 않는다.

앱의 ‘폴더 저장’ 성공은 iCloud·OneDrive의 원격 업로드 완료와 구분된다. 업로드 상태는 해당 클라우드 앱에서 확인한다. 쓰담 서버에는 음성 사본을 전송하지 않는다.

## 복원

기록 ZIP과 녹음 폴더는 별개이므로 함께 보관한다. ZIP 복원 버튼만으로 음성이 자동 복원되지는 않는다.

같은 컴퓨터에서는 쓰담을 종료하고 기존 `data/audio`를 별도로 보존한 뒤, 사본의 `audio/` 내용을 상대경로 그대로 `data/audio`에 복사한다. 맥의 기본 데이터 위치는 `~/Library/Application Support/쓰담/data`이다.

다른 컴퓨터에서는 DB 안의 녹음 경로도 새 데이터 위치에 맞게 다시 연결해야 한다. 기존 파일을 덮어쓰기 전에 지원을 요청한다. 기기별 녹음 폴더에도 같은 내용의 `복원 안내.txt`가 들어간다.

폴더 백업을 끄거나 다른 폴더로 바꾸면 음성 백업도 꺼진다. 이미 둔 사본은 삭제하지 않는다. 옛 DB를 복원하더라도 현재 컴퓨터의 백업 폴더와 음성 전송 선택을 유지한다.
