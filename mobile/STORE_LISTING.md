## 등록 순서

### 아이폰 (App Store Connect)
1. Xcode → 설정 → Accounts에 Apple ID 로그인 (개발자 계정)
2. 개발자가 빌드하면 번들 ID `kr.sseudam.app`과 iCloud 컨테이너가 자동 등록됨
3. [App Store Connect](https://appstoreconnect.apple.com) → 앱 → **+ 새로운 앱** → iOS · 이름 '쓰담 – 말로 쓰는 학생 관찰 기록' · 기본 언어 한국어 · 번들 ID `kr.sseudam.app` · SKU `sseudam-ios`
4. 개발자가 TestFlight로 업로드 → TestFlight 탭에서 내부 테스터(본인) 추가 → 아이폰 TestFlight 앱으로 설치
5. 스크린샷(6.9", 6.5") · 위 설명 · 개인정보 설문 → 심사 제출

### 데이터 보안 (Data safety) 답안
**요약: 개발자는 사용자 데이터를 받지 않습니다.** 녹음·글·사진 글자 읽기는 기기 안에서 처리합니다. 다만 ① 선생님이 컴퓨터와 연결하면 녹음·메모가 선생님 본인의 구글 드라이브(선생님이 만든 Apps Script)로 전송되고, ② 구글 ML Kit(사진 글자 읽기 라이브러리)가 진단 정보를 구글에 보냅니다. 플레이 기준으로는 '기기 밖으로 전송'이 수집에 해당하므로 아래처럼 **보수적으로 신고**하는 것을 권합니다.

| 질문 | 답 |
|---|---|
| 앱이 필수 사용자 데이터 유형을 수집하거나 공유하나요? | **예** |
| 전송 중 모든 데이터 암호화? | **예** (HTTPS: script.google.com, ML Kit) |
| 사용자가 데이터 삭제를 요청할 방법? | **예** — 앱에서 기록·녹음을 직접 지우고, 앱 삭제 시 기기 데이터가 모두 지워짐. 드라이브에 올라간 파일은 선생님 본인 드라이브에서 삭제. (개발자 보관 데이터 없음) |
| 계정 만들기 | 없음 (로그인 없는 앱) |

수집 항목 (모두 **공유 아님**, **처리: 일시적 아님**):

| 데이터 유형 | 수집 | 필수/선택 | 목적 | 비고 |
|---|---|---|---|---|
| 오디오 › 음성 또는 소리 녹음 | 예 | **선택** (컴퓨터 연결 시에만) | 앱 기능 | 선생님 본인 구글 드라이브로 전송, 개발자 수신 없음 |
| 앱 활동 › 기타 사용자 제작 콘텐츠 (한 줄 메모) | 예 | **선택** (컴퓨터 연결 시에만) | 앱 기능 | 위와 같음. 메모에 학생 이름이 들어갈 수 있음 |
| 앱 정보 및 성능 › 진단 | 예 | 필수 | 분석 | ML Kit가 성능·오류 정보를 구글로 보냄 (구글: 제3자에 넘기지 않음) |
| 기기 또는 기타 ID | 예 | 필수 | 분석 | ML Kit 설치별 ID (사용자·기기 식별용 아님) |

수집하지 않음: 위치, 연락처, 사진·동영상(글자만 기기 안에서 읽고 사진은 보관·전송 안 함), 이름·이메일 등 계정 정보, 금융, 건강, 웹 기록, 광고 ID.
- 학생 기록 파일(.json)·CSV·PDF 내보내기는 선생님이 공유 시트로 직접 고른 곳으로만 보내짐 → '사용자가 시작한 전송'이라 공유 아님.
- ChatGPT·Gemini 연결은 앱이 요청문을 클립보드에 복사하고 그 앱을 열 뿐, 쓰담이 직접 보내지 않음 (붙여넣기는 선생님이 함).
- 참고: [ML Kit 데이터 공개](https://developers.google.com/ml-kit/android-data-disclosure)
- 대안: '연결된 본인 드라이브로의 전송은 개발자 수집이 아니다'라고 보고 오디오·메모를 빼고 ML Kit 두 항목만 신고할 수도 있지만, 심사 지적을 피하려면 위 표대로 신고하는 쪽이 안전합니다.

- 아동에게 호소하는 앱인가요? → **아니요** (마스코트는 있지만 교사 업무용 도구. 학생이 직접 쓰는 앱이 아님)
- 앱 설명·스크린샷에 '선생님용'임이 드러나 있음

### 앱 액세스 권한 (심사용 안내)
- **"모든 기능을 특별한 액세스 권한 없이 사용할 수 있음"** 선택 — 로그인·계정이 없음.
- 안내 문구(선택 입력): "로그인이 없습니다. '학생' 탭에서 반 만들기 → 명단에 '1 김민수 / 2 이서연'처럼 붙여넣으면 학생별 기록·PDF·사진 글자 읽기·ChatGPT/Gemini 요청문 복사를 모두 시험할 수 있습니다. '연결' 탭의 컴퓨터 연결은 선택 기능(컴퓨터용 쓰담의 QR 필요)이며, 없어도 다른 기능은 모두 동작합니다."

### 기타 신고 항목
- 광고: 없음 · 정부 앱: 아니요 · 금융 기능: 없음 · 건강: 없음 · 뉴스 앱: 아니요
- 데이터 백업: 학생 기록은 구글 클라우드 백업 제외(`data_extraction_rules.xml`), 새 폰으로 직접 옮기기만 허용

### 출시 순서 (Play Console)
1. [Play Console](https://play.google.com/console) → **앱 만들기** → 이름 '쓰담 – 말로 쓰는 학생 관찰 기록' · 기본 언어 한국어 · 앱 · 무료 → 정책 동의(본인이 직접 확인)
2. **테스트 › 내부 테스트** → 테스터 목록(본인·인회 선생님 등 이메일) 만들기
3. **새 버전 만들기** → Play 앱 서명 사용(기본값) → `app-play-release.aab` 업로드 → 버전 이름 1.0.0 (2) · 출시 노트 "첫 플레이 스토어 버전" → 저장·검토·내부 테스트로 출시
4. 테스터는 참여 링크로 설치해 확인 (녹음·사진 글자 읽기·PDF·ChatGPT/Gemini 열기)
5. **기본 스토어 등록정보**: 위 이름·짧은/자세한 설명, 아이콘·그래픽 이미지·휴대전화 스크린샷 업로드
6. **앱 콘텐츠**: 개인정보처리방침 URL → 앱 액세스 권한(제한 없음) → 광고(없음) → 콘텐츠 등급(위 설문) → 타겟층(18세 이상) → 데이터 보안(위 답안) → 포그라운드 서비스 권한(마이크) → 정부 앱·금융·건강(해당 없음)
7. **스토어 설정**: 카테고리 교육, 연락처 이메일·웹사이트
8. **국가/지역**: 대한민국 (필요하면 나중에 추가)
9. 개인 개발자 계정이면 프로덕션 전에 **비공개 테스트(12명 이상 · 14일)** 요건이 있을 수 있음 → 대시보드 안내대로 진행
10. **프로덕션 › 새 버전** (내부 테스트 버전 승격) → 검토를 위해 전송 → 심사(보통 수일)
11. 다음 버전부터는 `versionCode`를 1씩 올려 `./gradlew bundlePlayRelease`
